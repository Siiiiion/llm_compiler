## 3. P0：统一结构评估与实际生成，改变模型选择指标

### 3.1 已确认的实现差异

- [run_train_qwen3_clm.py](../../train/run_train_qwen3_clm.py) 默认 `METRIC_FOR_BEST_MODEL=eval_accuracy`。
- [train_qwen3_clm.py](../../train/train_qwen3_clm.py) 的 accuracy 是给定真实历史 token 后的逐 token 准确率。只有提供 `STRUCT_EVAL_SKETCH_PATH` 和 `STRUCT_EVAL_TARGET` 才启用结构回调，构建默认关闭。
- [eval_struct.py](../../validation/eval_struct.py) 另外实现了一份生成流程。`evaluate_structural_validity` 提前计算统一预算，回调 `_gen_func(..., _max_new_tokens)` 没有使用 policy 本次请求的 `_max_new_tokens`；生产 [gen_state.py](../../generation/gen_state.py) 则根据每阶段请求调整预算。
- 结构评估的上下文预算上限为 8,192，生产入口直接使用 tokenizer 的 `model_max_length`。当前固定 tokenizer 声明 131,072；生产默认预算下限/缩放为 256/4，结构评估函数默认 128/2。实际是否触及这些上限取决于 workload，但配置已经不一致。
- 结构评估的 `seed` 当前用于打乱并选择 workload；开启 sampling 时，还需要显式控制和恢复模型采样 RNG，才能隔离训练过程中的随机状态变化。

因此，token accuracy 高不保证完整调度正确；已知正确后缀回放通过，也不能证明结构评估和生产自由生成行为一致。

### 3.2 建议修改

抽出共享的生成配置、阶段预算计算、prompt 编码、continuation 解码和上下文限制，供生产、结构评估与训练回调共同使用。保留训练回调较小的评估范围，但评估配置要显式记录；若采用更小的预算，应单独说明，不能直接与生产结果比较。

固定训练验证集中的 workload、sketch、采样种子、每 workload 请求数 K、最大尝试次数以及 token/时间预算。评估时关闭 fallback，并区分模型生成、随机补齐和历史复用的来源。最少报告：

| 指标 | 用途 |
| --- | --- |
| 每阶段解析成功率、最终 state 生成率 | 定位首次决策、TBS、PRS 等阶段的损失 |
| 每 workload 的唯一可构建候选数 | 防止重复候选制造较高成功率 |
| 达到 K 个唯一可构建候选的 workload 比例 | 直接对应当前“有些 workload 生成不足”的问题 |
| 固定预算下唯一可构建候选数的 workload 宏平均 | 避免样本多的 workload 主导总体指标 |
| 生成 token 数、耗时、峰值显存、短缺数 | 判断是否依靠更大成本换取通过 |

checkpoint 优先依据固定预算下的唯一有效候选数或 K 达标率选择，accuracy/loss 作为辅助指标。GPU 输出正确性和延迟另行验收。最终 hold-out 测试集不用于选 checkpoint 或反复调参。

验收：同 checkpoint、同 prompt、同阶段请求、同生成配置下，评估与生产得到相同 prompt IDs、预算和解码协议；固定种子可复现，随机状态不污染训练。指标缺失或构建评估异常时应显式报告失败，不能静默以 token accuracy 替代。

## 4. P1：按目标分布训练，并补充模板覆盖

### 4.1 全量统计带来的新证据

本次只读扫描正式 raw 两个 split，按完整文本去重，并在 PPT 处分组；后缀与保存的 `suffix_text` 核对一致。

| 指标 | train | validation |
| --- | ---: | ---: |
| 记录数 | 556,948 | 34,178 |
| 各自 split 内完全重复的文本数 | 0 | 0 |
| 不同 PPT 前缀数 | 2,218 | 127 |
| 每前缀不同后缀数：最少 / 中位数 / 最多 | 7 / 183.5 / 1,844 | 28 / 198 / 1,512 |
| 只有一种后缀的前缀组 | 0 | 0 |
| 每 workload 的前缀数：最少 / 中位数 / 最多 | 1 / 1 / 4 | 1 / 1 / 4 |

这说明机械地删除重复文本没有明显收益，同一前缀下也已经存在多个组合。另一方面，大部分 workload 的前缀覆盖集中，仍需检查生产生成的 sketch 是否落在训练覆盖范围内。不同文本不等于不同有效 state/TIR，更不等于具有不同性能；这些层面的多样性尚未量化。

前述训练来源统计中，卷积约 55.83%、池化约 24.85%，batch matmul 与 matmul/dense 合计约 4.64%。该分类来自图名称，仅作诊断；如果目标重点是 Qwen/Transformer，当前样本分布值得做重平衡对照。不能据此断言失衡已经被证明是生成失败的原因。

### 4.2 建议修改

- 为正式 raw/Arrow 建立独立的行级索引，绑定原数据摘要，记录 row、workload、PPT 前缀、算子诊断类别与长度。当前 Arrow 保存前删除了 workload/source 字段；不必重写已发布数据，可用旁路索引驱动 sampler。
- 对照自然分布与受限重平衡：例如按 workload 使用温和的逆频率权重，再限制单个 workload 的重复次数；`N_w^(-alpha)`、`alpha=0.3–0.5` 可作为试验起点，需明确它是每行权重，并非已验证的最佳参数。保留自然分布的混合采样，避免反复过采样只有 7 条的 workload。
- 固定监督 token 总量、目标评估集合和生成预算，报告分算子与 workload 宏平均，确认目标类别改善时其他类别的变化。
- 先比较训练前缀与生产 sketch 的覆盖差距，再有针对性地补充合法 sketch 模板和资源配置；新增记录仍需通过相同的来源、解析、构建门禁。

验收：目标 workload 的唯一可构建候选数和 K 达标率提升，其他类别无不可接受退化；不能仅以重采样后的训练 accuracy 上升作为有效证据。

## 5. P1：验证“完整调度何时结束”的监督

### 5.1 已确认的事实与未确认的影响

[make_dataset_utils.py](../../data/make_dataset_utils.py) 对 CLM 使用 `add_special_tokens=False`，直接将完整文本编码结果复制为 labels，没有追加 EOS。本次通过 Arrow 列偏移读取两个 split 的所有最后一个 token，结果如下：

| split | 序列数 | 以 `<|im_end|>`（151645）结束 | 以 `<|endoftext|>`（151643）结束 |
| --- | ---: | ---: | ---: |
| train | 556,948 | 0 | 0 |
| validation | 34,178 | 0 | 0 |

生成端通常设置 EOS 停止，因此当前 CLM 数据没有在完整调度末尾显式提供 EOS 监督。**是否因此发生过生成、重复尾部或额外解析失败，目前没有实际自由生成统计，仍是待验证假设。** 这也不表示已发布数据违反重建规范：本轮按计划有意保留原文的 EOS 语义，没有改变训练任务。

### 5.2 建议方案

先采集每阶段请求字段数、实际生成 token 数、EOS/预算耗尽停止原因、完整调度之后的多余字段和解析失败类型。然后在独立数据版本中对照“完整调度末尾追加 EOS”与现有方案，或使用解析器可确认的阶段停止条件。

不能机械地在每个阶段 marker 后加 EOS，也不能按估计长度截断后缀；阶段边界必须来自实际 policy/state。追加 EOS 还需要同步调整完整文本与 Arrow 的验收协议，并核对 DPO 的终止处理，不能直接覆盖当前数据。即使大部分候选能解析，多生成造成的成本仍应计入固定预算评估。

## 6. P1：建立小规模真实性能监督

正式数据的 591,126 条来源均没有有效实测延迟，可以学习合法组合，但没有证据告诉模型哪些合法组合更快。这是从“可构建”走向“有优化效果”的必要缺口。

建议先建立训练侧的小型代表性测量集，而非立刻测完整几十万条：

1. 从训练划分中选择目标相关 workload，按 PPT 前缀和调度结构挑选候选，保留明确的候选、构建、运行正确性、测量四类状态。
2. 在独占 GPU 上运行，核对输出，再按相同 target、输入、warmup、重复次数及计时设置测量。保留所有有效结果及失败原因，必要时复测接近的候选，避免噪声制造偏好。
3. 优先做实测优质调度 SFT；样本足够后，在同 workload、同 PPT 前缀内构建可靠的快慢偏好，再开展 DPO/LAPO 对照。
4. 在隔离的评估集上比较固定搜索预算的 kernel 结果，并补充整网输出正确性和 `opt_level=3` 基线延迟。

不可将审计成功、占位成本或未知超时伪造为延迟，也不能把 hold-out 测量并入训练。合并测量文件进入 pair 构造前还应检查 workload 分组和记录级隔离，避免仅按文件名过滤。

验收：目标 workload 在固定搜索预算下的 best latency、相对基线收益及尾部退化有真实测量证据；整网收益单独报告，不能由 kernel 改善直接推断。

## 7. P2：扩大验证覆盖并减少无效搜索

当前按每 workload 的最短、中位、最长三条选样，覆盖长度但不保证覆盖不同 PPT 模板、变换结构、tile 组合或资源边界，而且源顺序使验证划分较晚被执行。

后续可在固定验证预算内，按 split × 类别 × 长度交错执行，并加入不同 PPT 前缀、变换类型、资源边界与固定种子随机样本。报告长度代表覆盖和模板覆盖各自的范围，不将确定性样本视为随机独立抽样。

当真实生成日志确认主要损失来自非法数值或组合时，再加入基于当前 state 的约束：SP 因子乘积、线程数、合法 stage/axis、展开参数等。约束需考虑字段间依赖，并经过 state 恢复和构建；单纯限制 token 字符集合不足以保证合法。若测得主要问题是后续阶段条件偏移，则用真实回调 prompt 构建阶段训练对照，保持完整有效决策与对应 state 上下文。

这两项值得继续，但应由失败类型和模板覆盖数据决定投入，优先级低于评估一致性和真实收益验证。

## 8. 推荐执行顺序

1. **当前任务保持原样运行**，完成第三步并处理 unresolved 样本；冻结任务结束后再迭代诊断和队列实现。第三步不能带着未获结论的样本直接宣称通过。
