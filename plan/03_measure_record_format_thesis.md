# 面向大语言模型调度生成的 TVM 测量记录表示

## 1. 数据格式概述

本文使用的 `0_merge.json` 文件采用 JSON Lines 格式组织 TVM AutoScheduler 的调度记录。文件中的每一行表示一个可独立解析、回放和验证的候选调度状态，其顶层结构由 `i`、`r` 和 `v` 三个字段组成。其中，`i` 表示测量输入，包含待优化工作负载及其调度状态；`r` 表示测量结果，记录该调度在目标硬件上的运行反馈；`v` 表示记录格式版本。

与普通自然语言训练语料不同，该文件中的每条样本均来源于 TVM 自动调度器的内部状态序列。其本质不是非结构化文本，而是对张量程序调度空间中一个候选状态的结构化描述。该描述同时包含计算任务、目标硬件、硬件资源约束和调度变换历史，因此能够作为大语言模型学习编译器调度决策的原生输入表示。

## 2. 字段语义

字段 `i` 对应 TVM AutoScheduler 中的 `MeasureInput`，由两部分构成：第一部分为 `SearchTask`，第二部分为 `State`。

`SearchTask` 记录调度任务的静态上下文，包括 workload key、目标硬件平台、硬件参数、target host、layout rewrite 选项以及任务输入名称等信息。以 RTX 4090 平台上的 BERT 数据为例，目标平台字符串中显式包含 `cuda`、`sm_89`、最大线程数、最大共享内存、寄存器数量和 warp size 等硬件约束。这使得模型输入不仅描述了“要优化什么计算”，还描述了“该计算将被映射到何种硬件资源上”。

`State` 记录候选 schedule 的变换历史。该部分由一系列 TVM AutoScheduler transform steps 构成，每个 step 均对应明确的调度原语或状态标记。例如，`SP` 表示 split，`FSP` 表示 follow split，`RE` 表示 reorder，`CA` 表示 compute at，`CHR` 和 `CHW` 分别表示 cache read 与 cache write，`CI` 与 `CR` 分别表示 compute inline 与 compute root，`AN` 表示循环注解。上述 step 按顺序排列，构成从初始计算图到当前调度状态的可回放变换轨迹。

字段 `r` 对应 TVM AutoScheduler 中的 `MeasureResult`，通常包含运行代价列表、错误码、总测量开销和时间戳。在生成评估数据中，`r` 可能为 `[[0], 0, 0, timestamp]`，表示该记录尚未经过真实 latency 测量，仅作为待评估或待补测的候选调度状态。字段 `v` 则用于标识 TVM 测量记录的序列化版本。

## 3. 基于 `PPT` 的调度生成任务构造

本文在 TVM 原生 transform step 序列中引入 `PPT` 作为提示边界标记，用于划分调度草图与后续决策空间。具体而言，`PPT` 之前的调度序列表示由 AutoScheduler SketchPolicy 生成的高层调度草图，`PPT` 之后的序列则表示需要由大语言模型补全的细粒度调度决策。

这种任务构造将张量程序调度问题转化为条件序列生成问题。给定计算图、目标硬件信息以及 `PPT` 之前的调度上下文，模型需要生成合法且高性能的调度后缀。相比从零生成完整 schedule，该方法显著降低了生成空间复杂度：传统 SketchPolicy 负责提供具有结构约束的初始草图，大语言模型则集中学习循环拆分、计算位置、缓存层级和线程映射等细粒度决策之间的组合模式。

因此，`PPT` 不仅是一个文本分隔符，更是调度搜索空间的语义分界点。它将“编译器规则驱动的结构生成”和“模型驱动的决策补全”连接起来，使两类方法能够在统一的状态表示中协同工作。

## 4. 学术论文中的方法表述

本文提出一种面向张量程序自动调优的大语言模型调度表示方法。该方法直接复用 TVM AutoScheduler 的测量记录作为基础数据结构，将计算任务、硬件目标、硬件资源约束以及调度变换历史统一编码为结构化序列。与传统 cost model 将调度状态压缩为人工特征向量不同，该表示保留了调度原语的顺序依赖、层级结构和可执行语义，使模型能够在接近编译器原生状态的表示空间中学习调度策略。

在该表示中，每个候选调度状态均可被还原为 TVM `MeasureInput`，并进一步交由 AutoScheduler、LocalBuilder 或 LocalRunner 进行合法性验证、代码生成和真实性能测量。因此，模型生成结果并非孤立的文本输出，而是能够重新进入编译器优化闭环的可执行调度状态。这一性质为后续的结构合法性评估、真实 latency 反馈和偏好优化训练提供了统一的数据基础。

进一步地，本文通过 `PPT` 标记构造调度草图条件生成任务。该设计将传统自动调度器生成的高层 sketch 作为模型 prompt，将 sketch 之后的调度决策作为模型学习目标。由此，大语言模型不需要替代完整的编译器搜索流程，而是在编译器提供的合法草图基础上进行高质量决策补全。该方式兼顾了传统自动调度方法的规则可靠性和大语言模型的序列建模能力，为 LLM 与张量编译器自动调优的结合提供了一种可落地的中间表示。

## 5. 创新性总结

上述数据格式的创新性主要体现在三个方面。

第一，本文提出了编译器状态原生序列化的调度建模方式。该方式不再将 schedule 简化为离散标签或统计特征，而是直接使用 TVM AutoScheduler 的 transform step 序列作为模型输入，使调度原语、硬件约束和状态演化过程同时被模型感知。

第二，本文构造了可回放、可验证、可测量的生成目标。模型输出的调度序列能够被 TVM 重新解析为 `MeasureInput`，并进入代码生成、构建和运行测量流程。这使得语言模型生成与编译器真实性能反馈之间形成闭环，为后续基于 latency 的监督学习、偏好优化和强化式调优奠定基础。

第三，本文通过 `PPT` 边界标记提出了调度草图到调度决策的条件生成范式。该范式并不试图完全替代 AutoScheduler，而是将大语言模型嵌入到 SketchPolicy 的状态生成阶段，使模型专注于调度后缀补全。相比完全黑盒的 schedule 生成方法，该设计具有更强的结构可控性、系统兼容性和工程可落地性。

综上，该 JSONL 测量记录格式不仅承担数据存储作用，更构成了本文方法的关键中间表示。它将 TVM 自动调度器的可执行状态空间转化为大语言模型可学习的序列空间，并通过 `PPT` 标记建立了从调度草图到高性能调度决策的生成式优化路径。
